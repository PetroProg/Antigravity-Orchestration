# Project: <project-name>

## Стек и архитектура
- Укажи язык, фреймворк, БД, Docker / инфраструктуру.
- Основные директории: `app/`, `src/`.

## Критичные зоны и ограничения
- Никогда не коммитить `.env`, секреты, ключи и локальные базы.
- Задавать таймауты на внешние сетевые вызовы, валидировать ввод.

## Команды проверки
- Сборка/запуск: `docker compose up -d --build`
- Тесты: `<test command>`

## Рекомендуемые модели
- Основная разработка: сбалансированная кодерская модель (Sonnet / Argon).
- Мелкие правки и тексты: быстрая модель (Flash / Hydrogen).

## Git и GitHub
- После завершения значимых изменений проверять наличие папки `.git` (и настроенного `remote`), делать коммит и каждый раз пушить изменения на GitHub (`git push`).
- Перед коммитом и пушем обязательно проверять `git status` / `git diff`, чтобы в репозиторий не попали `.env`, секреты, ключи, сессии и локальные базы.
